# 本轮评审：正向 WebSocket 客户端 Token 支持

## 对照表

| 关注点 | 检查结论 | 相关位置 |
|---|---|---|
| 客户端是否在握手阶段发送 token | `loop_client` 每次连接/重连构造请求并设置 `Authorization: Bearer` | `runbot/src/connection.rs` |
| token 是否进入 URL | 未拼入 URL/query，只作为 header value | `build_client_request` |
| 默认兼容性 | 未配置 token 时不添加 Authorization 头 | `BotContextBuilder` / `build_client_request` |
| 凭据泄漏 | `BotContext` Debug 脱敏；header 标记 sensitive；日志不含 token | `runbot/src/bot_context.rs`、`connection.rs` |
| 错误处理 | 空 token、非法 header 字符返回配置错误；握手失败沿用重连 | `runbot/src/connection.rs` |
| 测试覆盖 | 覆盖有无 token、敏感 header、非法 token、服务端 401 | `cargo test --lib` |

## 检查结果

- 客户端 token 不出现在 URL、连接日志或 Debug 输出中。
- 未配置 token 的连接行为与改动前一致。
- 服务端入站认证逻辑未被破坏，原有握手测试继续通过。
- `BotContext` 使用手动 `Debug`，避免新增 token 字段随 `#[derive(Debug)]` 泄漏。
- `BotContextBuilder` / `BotServer` 新增私有字段会影响外部 struct literal 构造，已记录为已知兼容性影响；`BotContext` 原本已有非公开字段。

## 已知问题

- `runbot/examples/client.rs` 的 `test_demo_command_ban` 在改动前即因 `connection not ready` 失败，与本轮改动无关。

## 结论

未发现阻塞性问题，等待用户验收。

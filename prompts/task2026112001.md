# 任务：为 runbot 反向 WebSocket 接入增加 Token 认证

## 需求
为 runbot 的 WebSocket 服务端接入增加 token 校验，并形成可供评审的设计方案。

## 当前理解
- runbot 同时提供正向 WebSocket 客户端（`loop_client`）和反向 WebSocket 服务端（`loop_server`）。
- 本任务暂按“服务端接入时接受并验证 OneBot 反向 WebSocket 客户端提供的 token”理解；不涉及 `loop_client` 对外发送认证 token。
- 认证采用 WebSocket 握手 HTTP `Authorization: Bearer <token>` 头，与 OneBot 11 反向 WebSocket 常用约定一致。

## 目标
- 设计可选的服务端 token 配置、握手校验流程、错误响应、默认兼容行为与安全边界。
- 明确 API 变更及升级影响，列出待用户确认项。

## 范围
- 只编写方案文档，不改 Rust 源码、配置或示例，不运行测试。
- 涉及 `BotServerBuilder`、`BotServer`、`loop_server` 接入流程，以及相关示例/README 的后续实现建议。

## 验收
- 方案准确对应当前 WebSocket 服务端结构。
- 覆盖 token 正确/缺失/错误、未启用 token、连接拒绝及凭据保护等情形。
- 说明兼容性与仍需确认的问题，交由用户评审。

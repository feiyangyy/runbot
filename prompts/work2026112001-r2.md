# 本轮工作记录：正向 WebSocket 客户端 Token 支持

## 完成内容

- `runbot/src/bot_context.rs`
  - `BotContextBuilder::access_token(...)` 新增客户端出站 token 配置。
  - `BotContext` 保存私有 token 字段，并改为手动 `Debug` 实现，token 输出为 `[REDACTED]`。
  - `build()` 拒绝空 token。
- `runbot/src/connection.rs`
  - 新增 `build_client_request`：每次连接/重连根据 URL 重新构造 WebSocket Upgrade 请求。
  - 配置 token 时设置 `Authorization: Bearer <token>`，并标记 header value 为敏感值。
  - token 不会拼入 URL/query；空 token 或非法 header 字符直接返回配置错误。
  - 未配置 token 时不添加 Authorization 头，保持原有连接行为。
  - `loop_client` 握手失败仍走既有重连等待逻辑。
- `runbot/examples/client.rs`、`README.md`
  - 正向 WS 示例支持通过 `RUNBOT_ACCESS_TOKEN` 可选启用 token。
  - 补充上游需配置相同 token、默认无 token 兼容、明文 WS 凭据泄露风险说明。
- `doc/websocket-token-auth.md`
  - 将方案扩展为服务端入站校验与客户端出站发送两个方向。
  - 补充客户端流程、API、失败行为、安全边界、兼容性和验收标准。

## 验证结果

- `cargo check --workspace --all-targets`：通过。
- `cargo test --lib`：36 passed。
- `cargo test --workspace --all-targets`：新增测试通过；`runbot/examples/client.rs` 既有 `test_demo_command_ban` 因 `connection not ready` 失败，修改前基线同样失败。

## 兼容性

- 未配置 token 时行为不变。
- `BotContextBuilder` 新增私有字段，直接 struct literal 构造会受影响；链式用法不受影响。`BotContext` 本身已有非公开字段，外部原本就不能直接构造。
